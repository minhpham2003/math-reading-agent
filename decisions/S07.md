# S07 — Selecting a Reasonable Reading Range

**Status:** Design closed — approved by reader  
**Last updated:** 2026-11-01

**Scenario:** The reader selects a reasonable section or page range. The agent evaluates its scope and identifies several conceptual units.

## Approved design decisions

### S07-D01 — Analyze after entering the workspace

**Status:** Approved — 2026-11-01

**Decision: Option B — Workspace-first analysis**

Keep the **New Session** popup simple. After clicking **Create Session**, the reader enters the nearly full-screen reading workspace.

Within the workspace, the agent:
- Analyzes the selected reading range.
- Assesses whether the scope is reasonable.
- Identifies its conceptual structure.

The existing layout is preserved: **agent on the left, PDF on the right**.

**Alternatives considered**
- **A — Popup analysis:** Expand the New Session popup to show the analysis before creating the session.
- **C — Two-stage preview:** Show a compact analysis in the popup and the full analysis in the workspace.

**Rationale**

Keep session creation separate from analysis of the mathematical source. This avoids making the popup overly complicated and allows the reader and agent to inspect the PDF together.

**Approval evidence:** The reader chose B in the A/B/C discussion.

**Implementation:** Not started.  
**Verification:** Not performed.

---

### S07-D02 — Present a proposed reading plan

**Status:** Approved — 2026-11-01

**Decision: Option C — Proposed reading plan**

After entering the workspace, the agent analyzes the selected range and generates a **proposed reading plan** in the existing collapsible panel.

The reader can:
- Review the conceptual units.
- Request modifications.
- Accept the plan with one click.

Guided reading of the first conceptual unit begins **only after acceptance**.

**Alternatives considered**
- **A — Conversational:** Present the analysis in chat and generate a plan after confirmation.
- **B — Automatic:** Populate the reading plan and allow reading to start without explicit approval.

**Rationale**

The proposed plan gives the reader useful structure immediately while preserving control over the learning strategy. One-click acceptance avoids unnecessary friction.

**Approval evidence:** The reader chose C in the A/B/C discussion.

**Implementation:** Not started.  
**Verification:** Not performed.

### S07-D03 — Informative conceptual-unit entries

**Status:** Approved — 2026-11-01

**Decision: Option B — Informative**

Each unit in the proposed collapsible reading plan displays:
- A concise conceptual title.
- Its location in the source (with an explicit page-numbering convention).
- A brief description of what the reader should understand.

Do not display time estimates, key-object catalogs, or long objectives by default. The reading plan remains a proposal requiring reader acceptance under D02.

**Alternatives considered**
- **A — Minimal:** Title and PDF location only.
- **C — Detailed:** Title, location, estimated time, learning objective, and key mathematical objects.
- **B with expandable details:** Proposed but not selected; do not assume it is approved.

**Rationale**

Give enough orientation to understand the conceptual sequence without overwhelming the agent panel.

**Approval evidence:** The reader selected “B” in the A/B/C/B-with-expansion discussion.

**Implementation:** Scripted prototype example in [5dc95eb](https://github.com/minhpham2003/math-reading-agent/commit/5dc95eb5b6231f438e7334b11a750588f2ee4862); no automatic PDF analysis.
**Verification:** Pending.

### S07-D04 — Navigate and highlight conceptual units

**Status:** Approved — 2026-11-01

**Decision: Option B — Navigate and highlight**

Clicking a conceptual unit in the reading plan should navigate the PDF to the relevant passage and temporarily highlight it. This action does **not** automatically generate an agent response.

**Alternatives considered**
- **A — Navigate:** Move the PDF to the unit start without highlighting.
- **C — Navigate, highlight, and explain:** Also trigger an agent explanation.

**Rationale:** Direct source navigation without unnecessary agent messages.

**Approval evidence:** Reader explicitly selected “B” when presented with A/B/C.

**Implementation:** [2186cd5](https://github.com/minhpham2003/math-reading-agent/commit/2186cd5b1b44442b526af2e97ca387fe36c67faf) implements clickable units and temporary source-summary highlighting in the static prototype. Live PDF navigation requires a PDF viewer.
**Verification:** Pending browser interaction testing.

### S07-D05 — Hybrid editing of proposed plans

**Status:** Approved — 2026-11-01

**Decision: Option C — Hybrid editing**

The reader may edit conceptual units directly (for example, titles, order, boundaries, and removals), **or** request a conversational agent revision. Agent-proposed revisions require the reader to review them before acceptance. Guided reading still begins only after explicit plan acceptance, as required by D02.

**Alternatives considered**
- **A — Conversation only:** Request all changes through the agent.
- **B — Direct editing:** Modify the plan without conversational revisions.

**Rationale:** Preserve reader control over small changes while supporting substantial agent-assisted changes.

**Approval evidence:** Reader chose C in the S07-D05 A/B/C discussion.

**Implementation:** [abcb89c](https://github.com/minhpham2003/math-reading-agent/commit/abcb89c23fe3c3e98a0f7a38754e7ea893a56cb2) adds prototype controls for title edits, reordering, removal, scripted revision and acceptance; no real agent backend.
**Verification:** Pending.

### S07-D06 — Brief orientation after plan acceptance

**Status:** Approved — 2026-11-01

**Decision: Option B — Brief orientation**

After acceptance, navigate to the first conceptual unit. The agent offers a short introduction identifying what to pay attention to, without explaining the mathematics or requiring an opening answer. The reader begins independently and initiates conversation when ready.

**Alternatives:** A — Immediate start; C — Interactive opening question.

**Approval evidence:** Reader selected B.

**Implementation:** [deb3541](https://github.com/minhpham2003/math-reading-agent/commit/deb354194477a5861a1f3f01276e5e31a9f9f4e6) — clicking Accept opens whichever unit comes first after user reordering and displays a brief scripted orientation. Real agent and PDF viewer not connected.

### S07-D07 — Detailed scope assessment

**Status:** Approved — 2026-11-01

**Decision: Option C — Detailed assessment (structured format)**

Before the proposed reading plan, the agent presents labeled fields for **Scope**, **Conceptual structure**, **Difficulty**, **Dependencies**, **Estimated reading time**, and **Recommendation**. The assessment should be qualified when uncertain and refer to the user's selection; avoid asserting precise time predictions as fact.

**Alternatives:** A — No explicit assessment; B — Brief assessment.

**Approval evidence:** The reader chose C and specifically liked the structured format shown in the proposal.

**Implementation:** [a5f2198](https://github.com/minhpham2003/math-reading-agent/commit/a5f2198f8d27a7f30083d1ed014388d404b632c4) — fixed Hatcher Chapter 3 simulated example; no automatic PDF analysis.

---

### S07-D08 flow refinement — Assessment before plan

**Status:** Approved — 2026-11-01

The workflow is sequential: assess selected range, allow conversational corrections, explicitly agree to the assessment, then reveal the proposed reading plan for editing and acceptance. The assessment and plan must not appear simultaneously as parallel stages.

**Implementation:** [15daa49](https://github.com/minhpham2003/math-reading-agent/commit/15daa49bc5522a2df7ecde8ce60c57a008338c84) — staged prototype UI.

---

### S07-D08 — Correct assessments conversationally

**Status:** Approved — 2026-11-01

**Decision: Option A — Correct through conversation**

Readers may tell the agent when its assumptions about their familiarity or the reading-range assessment are wrong. The agent acknowledges the correction and revisits its assessment and proposed plan as appropriate. Do not require a separate prerequisite-selection form.

**Alternatives considered:** B — Adjust assumptions form; C — Hybrid form and conversation.

**Approval evidence:** Reader selected A in the D08 discussion.

**Implementation:** Scripted prototype demonstration; no language model is connected.

## Open design questions

- Precise controls, save behavior, and agent revision protocol may be refined after prototype review.

## Constraints inherited from S02

- Dashboard-first navigation.
- New Session popup.
- Dark mode.
- Agent panel on the left and PDF on the right.
- Nearly full-screen reading workspace.
- Collapsible reading plan.

## Scope boundary

S07 covers reasonable reading ranges and their conceptual structure. Excessive scope belongs to S08; endpoints cutting through a mathematical unit belong to S09.

## Scenario closure — 2026-11-01

**Goal:** Assess a reasonable selected range and derive a reader-approved conceptual reading plan.

**Agreed flow:** Create Session → structured scope assessment → conversational correction if needed → explicit agreement → informative conceptual plan → hybrid editing (including drag-and-drop) → explicit acceptance → short orientation for the first selected unit. Conceptual unit navigation highlights relevant source excerpts in the prototype.

**Implementation:** A scripted static prototype is committed and published in [the PR preview](https://minhpham2003.github.io/math-reading-agent/previews/pr-1/). The actual agent, real PDF rendering and dynamic evaluation remain unimplemented; browser behavior was reviewed by the reader but automated end-to-end verification is outstanding.

**Deferred:** Scope negotiation for unrealistic ranges → S08; reading behavior and checkpoint strategy → S12. Do not add these to S07.

**Closure basis:** Reader approved the flow and asked to continue; subsequently identified that in-reading checkpoints exceeded S07's scope.

## Requirement classification audit — 2026-11-01

The audit preserves approved choices and does not resolve the existing duplicate D08 headings.

| Decision | Classification | Interface obligation | Agent-behavior obligation |
| --- | --- | --- | --- |
| D01 Workspace-first analysis | **Both** | Enter reading workspace after Create Session | Analyze selected range, scope and conceptual structure |
| D02 Proposed reading plan | **Both** | Display proposal in collapsible panel; wait for acceptance | Generate meaningful plan and defer guided reading until reader accepts |
| D03 Informative units | **Both** | Title, PDF location, concise description | Identify grounded units, anchors and useful descriptions |
| D04 Navigate/highlight | **Interface**, plus negative agent requirement | Click navigates and temporarily highlights | Do not generate an unsolicited explanation on click |
| D05 Hybrid editing | **Both** | Direct edits, revision requests and approval | Interpret revision requests, propose changes, await acceptance |
| D06 Brief orientation | **Both** | Open first unit after plan acceptance | Offer brief orientation without explaining mathematics or demanding an opening response |
| D07 Detailed assessment | **Both** | Show six labeled assessment fields | Assess actual scope, qualify uncertainty and time estimates |
| D08 flow refinement | **Both** | Assessment → explicit agreement → plan | Do not advance to plan before agreement |
| D08 Conversational correction | **Agent behavior** (with UI display) | No mandatory correction form | Interpret reader corrections, update assumptions, assessment and proposed plan |

**Verification:** Scripted/static prototype displays are not proof of the corresponding agent behaviors. Independently test each agent contract when implemented.
