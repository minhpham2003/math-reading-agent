# S24 — Agent suggests a branch / tangent creation and navigation

**Status:** Design in progress — approved decisions documented, scenario not closed  
**Updated:** 2026-11-01

**Original scenario:** The agent predicts that answering a question will significantly interrupt the main reading path and suggests a branch. The reader decides whether to accept.

**Terminology:** Parent may be the main branch or another tangent; child is a tangent branch. Tangent creation may also be requested directly by the reader.

## Approved design decisions

### S24-D01 — Copy the discussion; summarize on parent
**Classification:** Both. **Status:** Approved.  
**Decision:** Upon creation, copy the prerequisite/tangent-related messages into the tangent; replace their *visible representation* on the parent with a concise linked summary. Never delete underlying messages.  
**Agent:** Identify relevant discussion and draft the initial summary.  
**UI/data:** Copy with stable provenance; present summary on parent with history recoverable.  
**Alternatives:** Move; copy; start from a summary only. **Evidence:** Reader explicitly said messages “should be copied to the tangent branch” and “summarized on the main branch.”

### S24-D02 — Include preceding context as read-only
**Classification:** Both. **Status:** Approved — Option B, contextual inheritance.  
**Decision:** Include relevant immediately preceding parent messages as read-only context, separate from tangent-owned messages, and preserve origin/return anchor.  
**Agent:** Determine relevant context without confusing it with tangent discussion.  
**UI/data:** Clearly distinguish read-only context, owned messages, and provenance.  
**Alternative:** Only discussion messages. **Evidence:** Reader chose **B**.

### S24-D03 — Link the parent summary to the tangent
**Classification:** Interface (with data linkage). **Status:** Approved.  
**Decision:** The parent summary contains a clickable link opening its tangent; retain the link through later summary revisions.  
**UI/data:** Stable navigable parent↔child relationship.  
**Evidence:** Reader explicitly requested the link inside the summary.

### S24-D04 — Update the parent summary only on finishing
**Classification:** Both. **Status:** Approved — Option C, update on return.  
**Decision:** Initial summary remains static while tangent work continues; on explicit finishing, generate a replacement for review, never silently rewrite the parent.  
**Agent:** Generate updated summary when finishing is invoked.  
**UI:** Parent shows last approved/initial summary until save approval.  
**Alternatives:** Automatic live updates; never update; update on finishing. **Evidence:** Reader chose **C**.

### S24-D05 — Editable agent-proposed completion summary
**Classification:** Both. **Status:** Approved — Option A, explicit completion with editing.  
**Decision:** Finish tangent & return starts agent-generated editable summary; reader edits and clicks Save summary & return; then parent summary updates and navigates to origin. Merely switching branches does not finish.  
**Agent:** Produce faithful editable draft; preserve uncertainty; do not treat draft as approved.  
**UI:** Editable review and explicit save control; stable tangent link.  
**Evidence:** Reader chose **A** and specified an editable agent summary and button to make it the parent's summary. Return specifics in S25-D02.

### S24-D06 — Completed tangents can be reopened
**Classification:** Both. **Status:** Approved — Option A, reopen.  
**Decision:** Open completed tangent, continue full history; parent keeps last approved summary while editing; next finish proposes replacement for approval.  
**Agent:** Retain full history and draft revised summary after further discussion.  
**UI/state:** Reopening is editable, preserves older approved summary and history, switches status to In progress per D13.  
**Alternative:** Read-only completed tangent. **Evidence:** Reader chose **A**.

### S24-D07 — Unlimited nested tangents
**Classification:** Both. **Status:** Approved — Option A, nested tangents.  
**Decision:** A tangent can have child tangents without preset nesting depth; each child uses the same summary/return rules; finishing returns to its immediate parent.  
**Agent:** Resolve parent-child context appropriately at arbitrary depth.  
**UI/data:** Persist tree relationships and anchors; allow recursive creation and return.  
**Alternative:** Single depth. **Evidence:** Reader chose **A**.

### S24-D08 — Breadcrumbs and collapsible branch tree
**Classification:** Interface. **Status:** Approved — Option C, both navigation tools.  
**Decision:** Clickable ancestor breadcrumbs and a collapsible branch tree, highlighting current branch, with direct navigation and no permanently mandatory sidebar.  
**Alternative:** Breadcrumbs only or tree only. **Evidence:** Reader chose **C**.

### S24-D09 — Permanent tangent capability and two creation routes
**Classification:** Both. **Status:** Approved.  
**Decision:** A consistent message-level tangent icon can initiate tangent creation from anywhere; natural-language requests can perform the same operation directly without forcing the reader to click. For icon initiation, the clicked message anchors selection and agent identifies relevant surrounding context. For conversational initiation, agent finds the beginning of the ongoing tangent discussion and includes messages from there, with preceding context as appropriate.  
**Agent:** Interpret open-ended reader instructions, infer discussion origin, execute explicitly requested creation; don't present preset intellectual-intention menus.  
**UI:** Permanent unobtrusive message-level operation, not rotating suggested prompts.  
**Evidence:** Reader described permanent message icons, direct natural-language execution, then approved anchor-based icon selection and conversation-based extraction.

### S24-D10 — Create immediately, correct selection later
**Classification:** Both. **Status:** Approved — Option A, immediate create.  
**Decision:** On explicit creation request, infer selection and create/open tangent without another confirmation; let the reader adjust selection from tangent window. Proactive agent suggestions still require reader acceptance.  
**Agent:** Select relevant beginning and context; execute request without unnecessary repeated confirmation.  
**UI:** Editing available post-creation; preserve all messages.  
**Alternative:** Preview before creating. **Evidence:** Reader chose **A**, requesting edit capability in tangent.

### S24-D11 — Flexible message selection
**Classification:** Interface (with data correctness). **Status:** Approved — Option C, boundaries + individual messages.  
**Decision:** In tangent window, edit start/end boundaries and independently include/exclude individual messages; distinguish tangent-owned versus read-only context; do not delete original history.  
**Alternative:** Boundaries only or individual only. **Evidence:** Reader chose **C**.

### S24-D12 — Preview and apply selection edits
**Classification:** Interface (with transactional state handling). **Status:** Approved — Option B, preview then apply.  
**Decision:** Selection adjustments remain provisional until Apply changes; preserve existing tangent discussion and reconcile parent's visible extraction after apply.  
**Alternative:** Immediate application. **Evidence:** Reader chose **B**.

### S24-D13 — Visible tangent status
**Classification:** Interface (with state rule). **Status:** Approved — Option A, visible status.  
**Decision:** Parent summary and branch tree show In progress / Completed. Completion follows approved finish; reopening and continuing returns status to In progress.  
**Alternative:** No visible status. **Evidence:** Reader chose **A**.

## Behavioral boundary and interaction principle
Proactive *suggestion* is not proactive *execution*. Explicit reader commands such as “make this a tangent” authorize creation immediately. Intellectual goals are expressed in natural language; permanent controls support operations rather than supplying a menu of intentions.
